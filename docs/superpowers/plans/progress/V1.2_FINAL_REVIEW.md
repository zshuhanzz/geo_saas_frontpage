### 1.4 SaaS API — Onboarding / Auto-Discovery

- `/onboarding/auto-discover(/stream)` — 4-layer fallback 爬 + Gemini Flash 合成
  - Layer 1: robots.txt → sitemap
  - Layer 2: common sitemap paths
  - Layer 3: HTML nav parsing
  - Layer 3.5: common product / category paths
  - Layer 4: Gemini synthesis (always runs)
- **Layer 0 (v2-late)**: 用户可提供 `seed_urls`，直接抓取真实 anchor 产品，**bypass LLM 防 URL 幻觉**。返回 `seed_products: [{name, url}]` 字段。

- `/onboarding/wizard/complete` — 两分支 wizard (Own / OEM)，Shadow brand 自动 seed。
- `geo_settings_candidates` 审核 UI（接受 / 拒绝 / 忽略候选）。

## 2. SQL Migration 整合

**原始 16 个文件** (040-054 + 046b) 合并成 **3 个 consolidated 脚本**:

| Consolidated 文件 | 包含 | 执行时机 | 破坏性 |
|---|---|---|---|
| `migrations/consolidated_v1.2/part1_schema_and_backfill.sql` | 040 / 041 / 042 / 043 / 044 / 045 | **维护窗口内一次过** | ⚠️ 含 rename (042) / drop columns (044) / truncate agent_sessions (045) — 后两者需显式 user 批准 |
| `migrations/consolidated_v1.2/part2_templates_and_dashboards.sql` | 046 / 046b / 047 / 048 / 049 / 050 | part1 完成后立即 | 否，均是模板 wizard_config 写入 + cron 列 + metric seed 数据 |
| `migrations/consolidated_v1.2/part3_wizard_and_accuracy.sql` | 051 / 052 / 053 / 054 | part2 完成后立即（或与 part2 合并） | 052 的 workflow_step rename (`prompt_link` → `data_scope`) 需要所有 web 新版部署就位 |

每个 consolidated 脚本内部保留原 migration 的独立 BEGIN/COMMIT，**一段事务失败不影响后续**；单独从原文件 rerun 也可。

**数据完整性确认**: 所有 ad-hoc SQL (e.g., 本 session 手工改的 `geo_workflow_config` field type) 均已回写到对应 migration 源文件 (如 051 的 `mode_gate_picker` type)。env-specific 数据（Tmax topics / products / domains）是工作区级数据不入 migration (这是正确做法)。
